ALL-FREQS GPU EXPERIMENT — build notes
======================================

Base image : vendor_boot.img (SHA-256 fc38cbb7f...) — Redmi A5 kernel 5.15
             build (FDT at 0x20b9040, wrapper at FDT-0x40, v4 image).
Builder    : build_allfreq.py (dtc decompile -> edit GPU node -> dtc
             recompile -> byte-level reassemble; NO mkbootimg repack).

Each image adds these GPU OPP levels (kHz / uV) and sets sprd,dvfs-range-max
/ sprd,dvfs-scene-extreme to 0x0a:

  5      1100.0     950       0x08 (GPLL)

WARNINGS
--------
1. The base is a kernel 5.15 vendor_boot for the SAME device. It must be
   flashed together with the matching 5.15 kernel (and its ramdisk). Do
   NOT flash it onto Android 17 / kernel 6.18 firmware.
2. devfreq will list all 11 levels (1000...1600 included), but GPLL is a
   SINGLE fixed rate per image. Selecting 1.6 GHz in sysfs does NOT
   reprogram GPLL to 1.6 GHz unless you flashed the 1600mhz image.
3. The GPU rail (DCDC_GPU) is clamped by topdvfs (~750/781/912 mV). The
   voltage column above is cosmetic; raising it does not raise the rail.
4. Measured on this hardware: <= 1.1 GHz stable, 1.15/1.2 GHz artifacts,
   1.6 GHz hangs at boot (GPU fault 0x4002). The 5.15 base may behave the
   same; test at your own risk and keep the stock image for rollback.
5. OPP table entries are only labels unless assigned-clocks reprograms GPLL.
6. Do not flash these on top of SML/SPL changes you do not understand.

ALL of the above keep 5 OPP levels (384/512/614.4/768/<rate>), range-max=0x04,
scene-extreme=0x03. Only the top OPP + assigned-clock-rates change. The rail is

and 1.6 GHz is expected to hang at boot (GPU fault 0x4002).

Flash (your own action, never automated):
  fastboot flash vendor_boot vendor_boot_oc_1100mhz_1000mv.img
  fastboot reboot
Rollback: flash the original vendor_boot.img.
